# МЕДИКАМЕНТЕ MVP Architecture - Privacy by Design

## Обзор

Данный документ описывает целевую архитектуру MVP для компании «Медикаменте» с учётом принципов Privacy by Design (PbD). Архитектура обеспечивает самостоятельную запись пациентов на приём, управление записями для сотрудников ресепшена и аналитику на анонимизированных данных.

Текущая архитектура представляет оптимистический сценарий т.к. для реализации подобного проекта у компании нет достаточно ресурсов, чтобы уложиться в предлагаемые сроки (через пару месяцев). Стек технологий адаптирован под текущие ресурсы, но объем изменений требует большего количества разработчиков.

## Privacy by Design - Реализация принципов

Рассмотрим как реализуются принципы разработки Privacy by Design в предлагаемой архитектуре.

### 1 Proactive not Reactive (Превентивный подход)

- все данные разделены по доменам и предотвращают саму возможность не санкционированного доступа
- управление согласиями на обработку ПДн до начала сбора данных

### 2 Privacy as the Default Setting (Приватность по умолчанию)

- доступ только к необходимым данным по роли
- сбор только необходимого минимума данных

### 3 Privacy Embedded into Design (Встроенная приватность)

- Разделение доменов данных Profile Domain и Medical Domain изолированы
- Отдельные базы данных для каждой категории данных

### 4 Full Functionality (Полная функциональность)

- Аналитика на анонимизированных данных - бизнес-аналитика без доступа к ПДн
- Псевдонимизация с возможностью восстановления при необходимости (ключи в Vault)

### 5 End-to-End Security (Сквозная безопасность)

- Encryption at rest - шифрование данных в базах данных
- полное журналирование операций с чувствительными данными
- API Gateway - единая точка входа с аутентификацией и rate limiting

### 6 Visibility and Transparency (Прозрачность)

- Audit Service - журналирование всех операций с ПДн
- Доступ пациента к его данным, пациент видит, на что дал согласие

### 7 Respect for User Privacy (Уважение приватности)

- Client Portal - пациент управляет своими данными
- Право на удаление - возможность удаления данных по запросу. Текущая архитектура позволяет просто удалить данные клиента.

## RBAC

Описание ролей:

Patient (Пациент)

- **Профиль**: Чтение и редактирование только своих данных
- **Медицина**: Только чтение своих медицинских записей
- **Расписание**: Создание и управление своими записями
- **Аналитика**: Нет доступа

Receptionist (Сотрудник ресепшена)

- **Профиль**: Чтение всех профилей (ограниченные поля: ФИО, контакты)
- **Медицина**: Нет доступа к медицинским данным
- **Расписание**: Полный доступ ко всем записям
- **Аналитика**: Нет доступа

Doctor (Врач)

- **Профиль**: Чтение профилей назначенных пациентов
- **Медицина**: Чтение и редактирование медкарт назначенных пациентов
- **Расписание**: Управление своим расписанием
- **Аналитика**: Нет доступа

Analyst (Бизнес-аналитик)

- **Профиль**: Нет доступа к персональным данным
- **Медицина**: Нет доступа к медицинским данным
- **Расписание**: Нет доступа
- **Аналитика**: Только анонимизированные данные

## Технологический стек

| Категория      | Технология                      | Обоснование                                |
| -------------- | ------------------------------- | ------------------------------------------ |
| **Backend**    | Java, Spring Boot, Spring Cloud | Стек Tech Director'а, зрелая экосистема    |
| **IAM**        | Keycloak                        | Open-source, RBAC/ABAC, OAuth2/OIDC        |
| **OLTP DB**    | PostgreSQL                      | Надёжность, шифрование, соответствие стеку |
| **OLAP DB**    | ClickHouse                      | Быстрая аналитика, входит в стек           |
| **Logging**    | Elastic                         | Аудит, поиск по логам, стек компании       |
| **ETL**        | Apache Airflow                  | Гибкие пайплайны, Python экосистема        |
| **Secrets**    | HashiCorp Vault                 | Безопасное хранение ключей шифрования      |
| **Monitoring** | Victoria Metrics                | Входит в стек компании                     |
| **Container**  | Kubernetes                      | Масштабируемость, входит в стек            |
