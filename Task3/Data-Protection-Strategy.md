# Оценка Data Encryption at Rest and In Transit

Данные документ представляет оценку защищенности персональных данных в текущей архитектуре, содержит классификацию данных для защиты, обоснование необходимости защиты и перечень инструментов защиты в соответствии с заданием.

## Стратегия защиты данных компании «Медикаменте»

Для текущей архитектуры подобраны решения которые быстро обеспечат результат по защите данных.

Средства защиты будут применяться к:

- FileServer (Windows) с общими папками: Journals, Pacients, Laboratory Registry
- Excel-файлы как основное хранилище данных
- 1С:Бухгалтерия и 1С:Торговля и склад (файловый режим)
- ККМ (связь TCP/IP + OLE)
- Exchange Mail Server
- Внешняя лаборатория (Laboratory)

## Реестр данных: необходимость защиты и инструменты

Список сокращений:

- NTFS AC - NTFS Access Control Lists
- GPO - Group Policy Object
- EFS - Windows Encrypting File System
- RLS - row-level security (ограничения на уровне записи)
- ПДн — персональные данные
- ИБ — информационная база
- RLS — row-level security
- DLP — Data Loss Prevention

Для критичных файлов: 7-Zip с AES-256 шифрованием (архив с паролем) или EFS (правый клик → Properties → Advanced → Encrypt contents). **Доступ:** NTFS ACL — каждая папка Pacient*: доступ только лечащему врачу + регистратуре; использовать наследование с deny для остальных. **Классификация:** ручная — договоры переименовывать с префиксом `[CONTRACT]_`, медкарты `[PHI]_` для визуального контроля                                                                                                                                                                                                                                                         |

Exchange ниже) или SFTP. **Доступ:** NTFS ACL — папка Laboratory Registry: доступ только AD-группе MedStaff_Lab + MedStaff_Doctors (Read). **Псевдонимизация:** в Excel использовать ID пациента вместо ФИО; маппинг ID↔ФИО хранить в отдельном защищённом файле                                                                                                                                                                                                                                                                                      |

| Налоговая и финансовая отчётность                                                | Законодательные требования; конфиденциальность                                                                   | **Передача:** 1С-Отчётность / СБИС / Контур.Экстерн с КриптоПро CSP (ГОСТ Р 34.10-2012 ЭЦП, TLS). **At Rest:** копии отчётов хранить в зашифрованном архиве (7-Zip AES-256) или в папке с EFS. **Доступ:** отдельная папка Reports с ACL только для Finance + руководства                                                                                                                                                                                                                                                                                                                                                                                                                               |
| Номенклатура ТМЦ, закупки (1С:Торговля и склад)                                  | Целостность и конфиденциальность; возможно появление ПДн в документах                                            | **1С↔1С обмен (OLE):** ограничить сетевой доступ — обмен только внутри одного сервера или через localhost. **At Rest:** шифрование файловой ИБ 1С:ТиС. **Доступ:** настроить права в 1С — кладовщик видит только склад, без доступа к финансам                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| Данные в почте (Exchange Mail Server) — переписка, вложения                      | Передача конфиденциальных данных без контроля                                                                    | **In Transit:** включить Opportunistic TLS в Exchange (по умолчанию есть в Exchange 2013+); проверить: `Get-TransportConfig \| FL SmtpMaxMessagesPerConnection`. **Шифрование писем:** для писем с ПДн использовать S/MIME (настройка сертификатов в Outlook) или Office 365 Message Encryption (если есть подписка). **DLP (быстрый вариант):** Transport Rules в Exchange — создать правило: если тема/тело содержит «диагноз», «паспорт», «СНИЛС» → добавить disclaimer + отправить копию compliance officer. **Пример PowerShell:** `New-TransportRule -Name "PD Warning" -SubjectContainsWords "паспорт","СНИЛС","диагноз" -ApplyHtmlDisclaimerText "<p>Внимание: письмо может содержать ПДн</p>"` |
| Все данные на FileServer                                                         | Любой авторизованный пользователь может получить доступ к конфиденциальным файлам                                | **At Rest:** BitLocker на всех томах FileServer. **Доступ:** пересмотреть ACL всех папок — убрать широкие группы (Domain Users, Everyone); создать специфичные AD Security Groups. **Аудит:** GPO → Computer Configuration → Policies → Windows Settings → Security Settings → Advanced Audit Policy → Object Access → Audit File System (Success, Failure). **Мониторинг:** Event Viewer → Security; для удобства — бесплатный Event Log Explorer или пересылка в Graylog                                                                                                                                                                                                                              |
| Данные при передаче ККМ↔1С (TCP/IP, OLE)                                         | Перехват в сети; несанкционированный доступ к каналу                                                             | **Сетевая изоляция:** выделить ККМ и сервер 1С в отдельный VLAN (если управляемый свитч есть) или физически изолировать. **Firewall:** Windows Firewall на сервере 1С — разрешить входящие TCP только с IP ККМ на порт 1С. Команда: `New-NetFirewallRule -DisplayName "KKM to 1C" -Direction Inbound -LocalPort 1541 -Protocol TCP -RemoteAddress 192.168.1.100 -Action Allow`. **OLE:** работает локально — дополнительная защита не требуется                                                                                                                                                                                                                                                         |
| Резервные копии                                                                  | Содержат те же конфиденциальные данные; риск утери                                                               | **Шифрование бэкапов:** использовать Windows Server Backup с шифрованием или robocopy + 7-Zip AES-256. Пример: `robocopy D:\Data E:\Backup /MIR && 7z a -p"SecretPass123" -mhe=on E:\Backup.7z E:\Backup\*`. **Доступ:** папка с бэкапами — ACL только для администратора (не Domain Admins, а отдельная учётка Backup_Admin). **Хранение:** отдельный физический носитель или NAS с шифрованием; не на том же сервере                                                                                                                                                                                                                                                                                  |

## Дополнительные средства контроля

| Область                | Инструменты и настройка                                                                                                                                                                                                                                                                                                                                                                          |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Аудит доступа к файлам | **Windows Advanced Audit:** GPO → включить Object Access auditing. Просмотр: Event Viewer → Security → Event ID 4663 (file access), 4656 (handle request). **Отчёты:** PowerShell скрипт для выгрузки событий: `Get-WinEvent -FilterHashtable @{LogName='Security';ID=4663} -MaxEvents 1000 \| Export-Csv audit.csv`. **Бесплатные инструменты:** Event Log Explorer, FullEventLogView (NirSoft) |
| Классификация файлов   | **Ручная маркировка:** соглашение об именовании — `[PD]_`, `[PHI]_`, `[FIN]_` в начале имени файла. **Windows FSRM (File Server Resource Manager):** встроенная роль Windows Server — настроить File Classification Rules по содержимому (regex на паспорт `\d{4}\s?\d{6}`, СНИЛС). Действие: добавить тег в свойства файла                                                                      |
| Управление доступом    | **AD Security Groups:** создать иерархию — MedStaff (общая), MedStaff_Doctors, MedStaff_Lab, MedStaff_Reception, Finance. **Принцип:** deny by default — сначала убрать все разрешения, затем добавить конкретные группы. **Пересмотр прав:** ежеквартально выгружать ACL: `Get-Acl "D:\Data" -Recurse \| Export-Csv acl_report.csv` и сверять с актуальным списком сотрудников                  |
| Защита учётных записей | **Парольная политика GPO:** минимум 12 символов, сложность, смена каждые 90 дней, блокировка после 5 неудачных попыток. **Отключение уволенных:** интеграция 1С:ЗУП → AD через PowerShell скрипт (по расписанию проверять уволенных и отключать учётки)                                                                                                                                          |
| Сетевая изоляция       | **VLAN (если есть managed switch):** VLAN 10 — серверы, VLAN 20 — рабочие станции медперсонала, VLAN 30 — бухгалтерия/ККМ. **Windows Firewall:** на каждом сервере — блокировать всё кроме необходимого. **Wi-Fi:** отдельная сеть для гостей, не связанная с рабочей                                                                                                                            |
| Резервное копирование  | **Windows Server Backup** (встроенный) или **Veeam Agent Free** — ежедневный бэкап на внешний носитель. **Проверка:** ежемесячное тестовое восстановление. **Offsite:** копия на внешний USB-HDD, хранить вне офиса                                                                                                                                                                              |
